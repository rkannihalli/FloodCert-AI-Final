## BUG 1 — Batch Flood Cert: County Information Missing

**Problem:** When flood certificates are generated via the Batch run mode, the county field is blank/missing.

**Fix:**
- In the batch processing pipeline, ensure county is resolved for every address before generating the certificate.
- County must be derived from the geocoding result (use the `administrative_area_level_2` component from the geocoder response, or the equivalent field from your geocoding provider).
- If county is not returned by the geocoder, perform a secondary lookup using the FIPS county code from the NFIP map panel number (first 5 digits of the Community Panel Number are the FIPS state+county code — e.g., "48157" = Texas, Harris County).
- Never leave county blank on a generated certificate. If it cannot be resolved, flag the record with error "County could not be determined" rather than silently omitting it.

## BUG 3 — NFIP Map Number (Community Panel Number) Mismatch

**Root Cause Analysis:**
The system is selecting the wrong FIRM map panel. This happens because the property coordinates are being matched to the nearest panel centroid or a panel from the wrong jurisdiction layer (e.g., county-wide panel instead of city/municipality panel, or adjacent panel tile).

**CoreLogic Logic to Replicate:**
CoreLogic determines the Community Panel Number by:
1. Geocoding the property to a precise lat/lon.
2. Performing a **spatial intersection** of that lat/lon point against the FEMA NFIP FIRM panel polygons layer (not a nearest-centroid lookup).
3. The panel whose polygon **contains** the point is selected.
4. If the property sits on a panel boundary, the panel with the higher-precision community-level mapping (municipality over county) takes precedence.
5. The Community Panel Number = FIPS State Code (2 digits) + FIPS County Code (3 digits) + Panel Number + Suffix Letter.
   - NOTE: For incorporated municipalities/cities with their own FIRM, use the CITY's FIPS-based community number, NOT the county's.

## BUG 4 — NFIP Community Number Mismatch

**Root Cause Analysis:**
The system is returning a state+county FIPS-derived placeholder (e.g., "06077C") instead of the actual FEMA-assigned NFIP Community Number. The NFIP Community Number is a FEMA-specific identifier and does NOT always match the FIPS county code.

**CoreLogic Logic to Replicate:**
CoreLogic determines the NFIP Community Number by:
1. After identifying the correct FIRM panel via spatial intersection (Bug 3), reading the `DFIRM_ID` or `COM_NFO_ID` field from the FIRM panel attribute table.
2. Cross-referencing the FEMA NFIP Community Status Book (CSB) to get the official 6-digit NFIP Community Number.
3. For incorporated cities/towns with their own NFIP policy, using the CITY's community number — NOT the county's.

**Specific fixes:**

| Address | Your Output | Correct | Root Cause |
|---|---|---|---|
| 2625 Sumac Ave, Stockton, CA 95207 | 06077C | 060302 | Using county FIPS (077=San Joaquin) instead of FEMA community ID for City of Stockton |
| 107 Pierce St, Lewiston, ME 04240 | 23001C | 230004 | Using county FIPS (001=Androscoggin) instead of FEMA community ID for City of Lewiston |
| 11 Brabrook Rd, Acton, MA 01720 | 25017C | 250176 | Using county FIPS (017=Middlesex) instead of FEMA community ID for Town of Acton |

**Code fix:**
- Query the FEMA NFIP Community Status Book API or use the FIRM panel's community attribute to get the correct community number.
- FEMA CSB endpoint: `https://www.fema.gov/api/open/v1/fimaNfipCommunities`
- Filter by state and community name/FIPS to get the `communityNumber` field.
- Never construct the community number by concatenating state FIPS + county FIPS — always look it up from FEMA's authoritative source.
